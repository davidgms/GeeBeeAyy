MIUI Smart Refresh and GeeBeeAyy

Research on the Mi 10T Pro (MIUI 14, Android 12), 2026-10-01. Measured on the phone, plus public source code of MIUI mods.

Short answer. The 144 Hz setting is only a top limit. A MIUI system app called Battery & performance (com.miui.powerkeeper) picks a rate for whichever app is in front. It counts how many frames the app draws each second and picks the nearest screen rate.

The trap. While you sit on the ROM list, the app draws almost nothing, and MIUI drops the screen to 50 Hz. Then you open a game. The game wants 60, but a screen at 50 Hz can only show 50. So MIUI counts 50, keeps 50, and never goes back up.

What works today, no root: in a game, press Home and come back. MIUI starts again from 144, counts about 60, and settles at 60 Hz. This worked 3 times out of 3.

How MIUI picks the rate

Every app request goes through one cap. Standard Android requests (the ones GeeBeeAyy now sends) can only pick a rate under that cap.

DisplayFrameSetting.setScreenEffect(pkg, fps, cookie)
per-app rule from Xiaomi cloud"]
  B --> C["DisplayFeatureHal 'Smtfps'

(mode override by backdoor: yes)"]
  E["GeeBeeAyy requests
Surface.setFrameRate(59.73)
preferredDisplayModeId = 60 Hz"] -->|"only inside the cap"| D
  D --> F["Panel rate"]
  F -->|"an app cannot draw faster
than the panel"| C

The loop from the panel back to the frame count is the trap. Once X is 50, the count can never be more than 50.

Even a finger on the screen cannot help. Android's "touch boost" asks for the highest rate allowed, and the highest rate allowed is now 50.

Does the rate hurt the picture?

A GBA makes 59.73 frames a second. The best screen rate shows every frame for the same amount of time. Android never tears the picture. A bad rate shows as judder: uneven or missing frames.

50 Hz - what you had

12345678

1 frame in 6 is never shown. Scrolling and fast motion skip a little.

60 Hz - the target

12345678

Every frame, once each, for the same time. Lowest battery cost of the good rates.

120 Hz - also good

11223344

Every frame shown twice. Smooth, but the screen works twice as hard for no visible gain.

90 or 144 Hz - uneven

11233444

144 / 59.73 = 2.41, so frames stay on screen for 2 or 3 refreshes. Motion looks a little uneven, and battery use is highest.

This is why gameDisplayMode in ui/DisplayRate.kt asks for 60 or 120 and nothing else.

Ways around it

No rootTested

1. Home, then back to the game

MIUI starts again from 144 and settles at 60.

  • Safe. Nothing changes on the phone.
  • Lasts until you go back to the ROM list and wait.
No rootOnly shows

2. Developer options: "Show refresh rate"

A number in the corner shows the live Hz. It does not change the rate. Use it to check the trick above.

adb, no rootNot tested here

3. Turn off "Battery & performance"

adb shell pm disable-user com.miui.powerkeeper
Users report that the per-app limits stop. Undo with pm enable.

  • The same app also runs MIUI battery saver, limits on apps in the background, and battery stats. Expect more battery use.
  • A MIUI update can turn it back on.
Root + LSPosed

4. Hook modules

MIUI Performance Saver, HyperCeiler "Lock max FPS" and MIUIForceFPS. All three block DisplayFrameSetting.setScreenEffect inside PowerKeeper.

  • Needs an unlocked bootloader and root. Banking apps and Play Integrity can stop working.
  • One author warns that "DC dimming + high refresh rate" can change screen colours.
Root

5. SurfaceFlinger "backdoor" 1035

service call SurfaceFlinger 1035 i32 <mode> forces one mode.

  • This is a debug door, and MIUI already uses it ("mode override by backdoor: yes"). The two would fight over it.
  • Not for players.
In the app now

6. What GeeBeeAyy already sends

Surface.setFrameRate(59.73, FIXED_SOURCE) on the game surface, plus preferredDisplayModeId for 60 Hz on the window.

  • This is the correct Android API. It should work on Pixel, Samsung and other phones that follow it.
  • On MIUI it reaches SurfaceFlinger (both requests show in dumpsys), but the cap is above it.

What the app can do next

Small, safe

A. A one-time tip on MIUI

When the phone is Xiaomi, a game runs, and the screen rate is not 60 or 120, show a short tip once: "Your phone lowered the screen speed. Press Home and come back for smoother play."

The app can read the rate (Display.getRefreshRate()). It cannot change MIUI.

Experiment

B. Open games as their own task

MIUI resets when it sees a "home to app" switch. A game opened as its own task might start that reset. Not tested. It changes the Back flow and the recent-apps list, so it needs a test on the phone before any decision.

No

C. Keep the ROM list drawing all the time

This would stop MIUI from dropping to 50, but it would burn battery on a still screen to fool a battery feature. Rejected.
